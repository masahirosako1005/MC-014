## 1. システムの概要

「ミニ推し！」は、獲得した推し（キャラクター）が、実在の町（大阪市、尾道市、三原市）を自分の性格で旅する様子を見るWEBアプリです。

| 利用者 | 使う画面 | できること |
|---|---|---|
| 一般の利用者（ファン） | 利用者のアプリ（ポート3000） | 推しの足あとを見る、コードで推しやエリアを獲得する、推しをエリアへ連れ出す（神の手）、推しのおすすめを見る、推しに観光ルートを考えてもらう |
| 事務局（運営） | 事務局の管理画面（ポート3100） | 作品、キャラ、場所、イベント、天気、獲得コード、エリアと地図、自治体のアカウント、申請の承認、報告、利用者、スポットDBの管理 |
| 自治体（観光課など） | 自治体の管理画面（ポート3200） | 担当のキャラの変更の申請、獲得コードとQRコード、担当エリアのイベントと場所、報告の確認 |

### 1.1 前提と制約

- localhost で動かすデモです。データベースは使わず、JSONファイルに保存します。
- 画面からの通信先は、自分のサーバと国土地理院（地図のタイル）だけです（大会規定）。
- 外部のAIには接続しません。AIを使う箇所は、決まった規則で動くダミーにしてあります（8章）。
- 推しは喋りません。タイムラインや日記の文章は、すべて第三者の視点（天の声）で書きます。

## 3. 画面設計

### 3.1 共通の作り

- **画面の幅:** 最小320px。320〜374pxでは文字とボタンを少し小さくします。
- **スマホ（幅899pxまで）:** 下にタブを並べ、ホームでは地図の上に推しのカードと足あとの欄を重ねます。
- **PC（幅900px以上）:** 左にメニュー、中央に地図、右に推しのカードと足あとの欄を置きます。
- **色:** 指定の3色（teal / mint / yellow）を元にしています。半透明のガラスの部品（Liquid Glass）を使います。
- **動き:** 端末の「視差効果を減らす」設定がオンのときは、アニメーションを止めます。
- **画面の切り替え:** URLの `#/` の後ろで画面を切り替えます（例: `#/home`、`#/oshi/arisa`）。
- **ロゴとアイコン:** 左上に、アイコン（黄色の角丸に、目だけのピン。`public/favicon.svg`）と文字ロゴ（依頼者から受け取った画像の背景を透明にしたもの。`public/assets/brand/wordmark.png`）を並べます。アイコンはブラウザのタブにも使います。ロゴの案（ベクター）は `docs/logo/` にあります。
- **場所の種類のアイコン:** 線だけの簡単な形です（例: 寺社は鳥居、道場は交差した2本の刀）。
- **空の値を表示しない:** 条件しだいで出す部品が空のとき、画面に「null」と出ないよう、要素に子を足す共通の処理（append、replaceChildren など）で null と undefined と false を足さないようにしています（`public/js/core.js`）。事務局の画面で設定のJSONを出すときも、値が null の項目は書きません。

### 3.2 利用者のアプリ（ポート3000）

タブの並びは、ホーム、出会う、ミニ推し、推しのおすすめ、観光ルート、エリア、設定の順です。

| 画面 | URL | 主な表示と操作 |
|---|---|---|
| ホーム | `#/home` | 推しのカード（左右に切り替え。PCでは両脇に矢印、端では片方だけ）、地図（推しの印、通った道、スタート地点の旗、立ち寄った場所と順番の数字、乗り場の印）、足あとの欄（歩数・距離、天気、1日をなぞるスライダー、タイムライン、日付の切り替え）。タイムラインは「〇〇を出発した」（スタート地点）から始まる。PCではカードの後ろを、地図に出している時刻の天気の空にし、足あとの欄はカードのすぐ下から始める（余白を作らない） |
| ホーム: エリアの切り替え | ホームの中 | 推しを別のエリアへ連れ出す、家に帰す。神の手が推しをつまんで運ぶアニメーションを見せる |
| ホーム: 地図のボタン | ホームの中 | 観光ルートを考えてもらう、このエリアのイベント、エリア全体を見る、現在地、拡大・縮小。説明はカーソルを重ねたときだけ出す |
| 出会う | `#/meet` | QRコードをカメラで読む、またはコードを入力して、推しやエリアを獲得する。獲得の演出と「推す！」ボタン |
| ミニ推し | `#/oshi` | 「わたしの推し」（作品ごとの一覧、「推す！」「推し中！」の切り替え、ホームの並び順の変更）と「旅先で出会った推し」。並び順は「番号、左の矢印、顔と名前、右の矢印」の順で、ドラッグでも入れ替えられる |
| 推しのページ | `#/oshi/:id` | プロフィール、性格、好きなもの、日常、作中の出来事、足あとの集計、いつもの道 |
| 推しのおすすめ | `#/recommend` | 推しの好みの内訳、種類（色付き）とエリアの絞り込み、おすすめの場所の一覧と地図。推しの切り替えは顔のボタンから |
| 観光ルート（一覧） | `#/routes` | 推しが考えてくれた観光ルートの一覧。推しごとの絞り込み |
| 観光ルート（作成） | `#/route/new` | 推しの組み合わせ（推し×自分、推し×推し）、エリア、日にち、長さ、移動手段、気分を選ぶ |
| 観光ルート（結果） | `#/route/:id` | 地図、時刻順の流れ（乗り物、乗る・降りる駅）、天の声。上に「一緒に出かける」「条件を変えて」、下に「消す」 |
| エリア | `#/areas` | 獲得したエリア、いまいる推し、旅の履歴、カレンダー |
| 設定 | `#/settings` | プロフィール、地図の見た目、タイムラインの順、文字の大きさ、解釈違いの報告、ログイン（IDとパスワード）、初めからやり直す |
| 共通の部品 | — | 場所の詳しい情報のシート、イベントのシート、カレンダー、使い方の説明、知らせ（トースト） |

## 7. セキュリティ設計

2026-11-10 に3つのサーバを点検し、見つかった問題を直しました（7.4）。共通の処理は `lib/guard.js` にまとめています。

### 7.1 守るもの

| 守るもの | 守り方 |
|---|---|
| 利用者の進行状況 | 端末ごとのランダムなトークン（24バイト）。サーバにはハッシュだけを保存 |
| 利用者・自治体のパスワード | scrypt とユーザーごとのソルトでハッシュにして保存。照合は timingSafeEqual |
| 獲得コード | サーバでだけ照合し、画面には送らない |
| 運営の内容（キャラ、場所、イベント） | 事務局はログインが必要。自治体は担当の範囲だけで、キャラの変更は事務局の承認が必要 |
| サーバが動き続けること | 入力の形と大きさを確かめる。保存量と回数に上限を付ける |

### 7.2 セキュリティの要件と対策

| ID | 要件 | 対策 | 場所 |
|---|---|---|---|
| SR-01 | 画面からの通信先を自分のサーバと国土地理院に限る | Content-Security-Policy（script-src 'self'、connect-src 'self'、img-src は自分と国土地理院だけ、object-src 'none'、frame-ancestors 'none'）。外部のCDNは使わない | 3つのサーバ |
| SR-02 | 画面に他人の書いた文字をそのまま埋めこまない（XSS） | 文字は textContent で入れる。HTML の文字列しか受け取らない所（地図のツールチップ、管理画面の一覧）は esc() を通す。色は #RRGGBB の形だけ使う | core.js、map.js、avatar.js、admin.js、org.js、mapedit.js |
| SR-03 | 別のサイトや同じPCの別のポートから操作させない（CSRF） | Cookie は SameSite=Strict と HttpOnly。書きこみは Sec-Fetch-Site と Origin を確かめ、本文は application/json だけ受け付ける | guard.sameOrigin |
| SR-04 | ログインを総当たりさせない | 失敗はIDと接続元の組で数え、5回で5分止める。存在しないIDでも同じ時間をかける | guard.loginGuard、auth.js、orgs.js |
| SR-05 | 獲得コードを総当たりさせない | 見つからない回数を接続元ごとに10分で30回まで。超えたら10分止める | server.js |
| SR-06 | 担当の範囲を超えて操作させない | 自治体の全APIで担当のエリア・キャラを確かめる。エリアの追加と道のデータは事務局だけ。申請に入る項目を限る | org-server.js、map-admin.js、orgs.js |
| SR-07 | 入力の形と大きさを確かめる | 日付は本当にある日だけ。数値の範囲、文字の長さ、配列の数、決まった項目だけ。継承した名前（`__proto__` など）を通さない | calendar.validDay、guard.own、guard.eventProblem |
| SR-08 | 保存量が際限なく増えないようにする | 利用者を作るのは /api/state とログインだけ（接続元ごとに1時間200人まで）。報告は接続元ごとに1日50件。申請の確認待ちは自治体ごとに20件。設定資料は1キャラ20件・2MB。申請の絵は1キャラ10枚。送る本文は50KB（利用者）〜3MB（絵） | auth.js、server.js、orgs.js、rag.js、assets.js |
| SR-09 | 受け取る画像を確かめる | data URL の形式、先頭のバイト（PNG、JPEG、WebP）、1.5MBまで。ファイル名はサーバで決める。SVG は受け付けない | assets.js |
| SR-10 | エラーの中身を見せない | 共通のエラー処理で「入力が正しくありません」などだけを返す。形の崩れた Cookie でも止まらない | guard.errorHandler、guard.parseCookies |
| SR-11 | 管理画面は外から開けない | 事務局と自治体は 127.0.0.1 だけで待ち受ける | admin/server.js、org-server.js |
| SR-12 | ログインの後始末 | 8時間で切れる。ログアウトで Cookie を消す。パスワードを変えると、ほかの端末のログインを切る | admin/server.js、org-server.js |
| SR-13 | 個人情報を持たない | メールアドレスは受け付けない（ログインIDは半角英数字だけ）。報告の送り主は管理画面に出さない | auth.js、server.js |
| SR-14 | 秘密の値を Git に入れない | 利用者・自治体・設定資料・申請の絵の保存ファイルは .gitignore に入れる | .gitignore |
| SR-15 | その他のヘッダ | X-Content-Type-Options: nosniff、Referrer-Policy: same-origin、X-Powered-By を出さない | 3つのサーバ |
| SR-16 | 外部接続の禁止（大会規定） | 画面の通信先は自分のサーバと国土地理院だけ（CSP）。サーバから接続するのは国土地理院のタイル（道のデータを作るとき、実在の場所を集めるとき）だけ。AIや天気、Webからの収集の本物のコードはコメントの中に残し、動かさない。外部サイトへのリンク（公式サイトなど）は、利用者が押したときに開くだけで、アプリからは接続しない | 3つのサーバ、lib/place-collector.js、tools/build-routes.js |

### 7.3 担当の範囲（自治体）

| 操作 | 事務局 | 自治体 |
|---|---|---|
| キャラの変更 | すぐ反映 | 申請だけ（事務局の承認で反映） |
| エリアの追加・範囲の変更・道のデータ | できる | できない |
| 場所の追加・変更 | 全エリア | 担当エリアの中だけ |
| イベント | 全エリア | 担当エリアだけ（会場も担当エリアの場所） |
| 獲得コード | 全部 | 担当のキャラとエリアだけ |
| 報告 | 全部 | 担当キャラへの報告だけ |

### 7.4 点検で見つけて直した問題（2026-11-10）

| No | 重さ | 問題 | 直し方 |
|---|---|---|---|
| 1 | 高 | 観光ルートの日付に 9999-99-99 を送ると、日を進める処理が終わらず、3つのサーバ全部が止まった | 日付が本当にある日かを確かめ、日のくり返しに上限を付けた |
| 2 | 高 | 自治体がイベントの tags に文字列以外を入れると、推しの行動の計算が例外で止まり、利用者と事務局の画面も止まった | イベントの形と長さの確かめを事務局と共通にした |
| 3 | 中 | Cookie はポートで分かれないため、同じPCの別のポートから管理画面へ書きこめた（text/plain の本文） | Sec-Fetch-Site と Origin を確かめ、JSON 以外の本文を断る |
| 4 | 中 | Cookie のない送信のたびに利用者が作られ、保存ファイルが際限なく大きくなった | 作るのは /api/state とログインだけにし、接続元ごとの回数を制限 |

### 7.5 大会規定の外部接続（2026-11-10 に確認）

大会規定は「外部のAPIに接続することは禁止。地図を使う場合は国土地理院の無料WEBサービスにアクセスしてよい」です（要件定義）。コードと実際の通信の両方で確かめ、違反はありませんでした。

| 確かめたこと | 結果 |
|---|---|
| 画面の通信（ブラウザが実際に通信した相手）。利用者のアプリ10画面、自治体8画面、事務局14画面を順に開いた | 自分のサーバと国土地理院（cyberjapandata.gsi.go.jp）だけ |

| サーバから外への接続 | 国土地理院のタイルだけ（管理画面で「道のデータを作る」「実在の場所を集める」を押したとき） |
| AI、天気のAPI、Webからの収集 | 本物のコードはコメントの中にあるだけで動かない |

外部サイトへのリンク（場所の公式サイト、観光協会、イベント情報、要件定義にあるスタンプラリーのサイト）は、利用者が押したときに新しいタブで開くだけで、アプリから接続することはありません。開発中に使った接続（npm のインストール、Wikimedia Commons から取った肖像画）は、動かしているときの接続ではありません。

## 10. 試験シナリオ

### S-01 初めて使う人が推しの1日を見る

1. アプリを開く（Cookie なし）。
2. ホームに、ありさと武蔵のカードが出る。
3. 地図に推しの印と今日通った道、スタート地点の旗、立ち寄った場所と順番の数字が出る。タイムラインは「〇〇を出発した」から始まる。
4. 足あとの欄で、スライダーをなぞる。推しの位置と様子が、その時刻のものに変わる。
5. 前の日に切り替える。リングと日記が出て、1日全体の道が出る。

**確かめること:** 利用者が作られる。足あとが出る。タイムラインがスタート地点から始まり、地図に旗が出る。天気と時刻が合っている（T-01〜T-03、T-40）。

### S-02 コードで新しい推しを獲得し、ホームに並べる

1. 「出会う」でコード（例: `MINI-NAGI-7K2F`）を入力する。
2. 獲得の演出が出る。
3. ミニ推しタブで「推す！」を押す。表示が「推し中！」になる。
4. 「ホームの並び順」で入れ替える。
5. ホームで、その順に並ぶ。

**確かめること:** 獲得、ホームへの追加、並び順の保存。正しくないコード・獲得済みのコードは断られる（T-04、T-07）。

### S-03 推しを別のエリアへ連れ出す

1. ホームでエリアのボタンを押し、獲得したエリアを選ぶ。
2. 神の手が推しをつまんで運ぶアニメーションが出る。
3. タイムラインに神の手の移動（黄色の背景）が出て、推しが移動先で過ごす。
4. 家に帰す。

**確かめること:** 獲得していないエリアには連れて行けない。夜遅くに移したときの帰る・泊まる（T-05、T-06）。

### S-04 推しに観光ルートを考えてもらう

1. 観光ルートタブで、推し、組み合わせ、エリア、日にち、長さ、移動手段、気分を選ぶ。
2. 推しがルートを考える。地図と時刻順の流れ、乗る・降りる駅、天の声が出る。
3. 保存したルートを一覧から開き、消す。

**確かめること:** 時刻の順、選んでいない移動手段を使わない、推し×推しの書き方（T-10〜T-13）。

### S-05 自治体がキャラの変更を申請し、事務局が承認する

1. 自治体の管理画面にログインする。
2. 担当キャラの編集で、設定資料を登録し、「AIにおまかせ」を押す。参照した資料と提案が出る。
3. 値を手で直して申請する。この時点ではアプリに反映しない。
4. 事務局の管理画面で申請を開き、承認する。
5. アプリに反映される。

**確かめること:** 担当の範囲、承認までの非反映、提案の内容（T-18、T-20、T-23）。

### S-06 事務局が新しいエリアを作る

1. 事務局の「マップ」で多角形を描いてエリアを足す。
2. 頂点を動かして範囲を直し、最初の駅を決める。
3. 道のデータを作り、実在の場所を集める。
4. 自治体に割り振る。自治体はそのエリアに聖地のスポットを足せる。

**確かめること:** エリアの追加は事務局だけ。自治体は担当エリアの中だけ（T-24、T-25）。

### S-07 悪意のある送信に耐える

1. 観光ルートの日付に 9999-99-99、2026-02-31 を送る。
2. 同じPCの別のポートを名乗って（Sec-Fetch-Site: same-site）、管理画面にログインを送る。
3. text/plain の本文、壊れた JSON、壊れた Cookie を送る。
4. `__proto__`、`constructor` を推しや場所の種類として送る。
5. 自治体として、イベントの tags に {}、時間に [null, null]、ほかのキャラの絵を送る。
6. `../` を含むパスで、保存ファイルを読もうとする。
7. ログインせずに管理画面のAPIを呼ぶ。

**確かめること:** サーバが止まらない。すべて 4xx で断り、エラーの中身を漏らさない（T-28〜T-36）。

## 12. 残っている課題と公開時の注意

### 12.1 公開するときに必ずすること

| 項目 | 内容 |
|---|---|
| 事務局のパスワード | 環境変数 `ADMIN_PASSWORD`（と `ADMIN_ID`）で変える。デモ用の値は README に載っている |
| 自治体のデモ用アカウント | パスワードを変えるか、止める（デモ用の値はソースと README に載っている） |
| デモ用の全部獲得 | `DEMO_UNLOCK=off` で止める。止めないと、だれでも全部の推しとエリアを獲得できる |
| HTTPS | 利用者のアプリを公開するときは、HTTPS の前段（リバースプロキシ）を置き、Cookie に Secure を付ける |
| 管理画面 | 127.0.0.1 のままにし、外に公開しない |

### 12.2 残っている課題

| 項目 | 内容 |
|---|---|
| 回数制限の単位 | 接続元（IPアドレス）ごとに数える。リバースプロキシの後ろに置くと全員が同じ接続元になるため、その場合は `X-Forwarded-For` を信頼する設定が必要 |
| 保存の方式 | JSONファイル全体を書き直すため、利用者が数万人になると遅くなる。本番ではデータベースに移す |
| 利用者のセッション | 有効期限がない（1年の Cookie）。使われていない利用者を消す仕組みもない |
| 獲得コードの長さ | 推しの名前の後ろの4文字（約6.8万通り）。本番では、もっと長いランダムな文字列にする |
| 画像の権利 | GUMI の写真は肖像権と使用許可、もやしペンギンと堀江凪のイラストは作者の許可を、公開前に確かめる（README「絵の出典」） |
| 文字ロゴの解像度 | 受け取った画像は 168×68 と小さく、大きく表示するとぼやける。大きく使うときは元のデータ（ベクターか大きな画像）に差し替える |
